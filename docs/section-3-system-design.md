### 3.1 System Overview

The proposed system runs on an ESP32 microcontroller in a Wokwi simulation environment that supports live sensor monitoring and on-device ML inference. The design is purposefully structured into a two-tier system. Tier 1 is an edge IoT layer which transmits sensor data from MEMS and environmental sensors to a Blynk cloud dashboard with anomaly notifications based on thresholds. Tier 2 is an AI inference layer with an XGBoost classifier trained to operate on stored SECOM process samples. The two tiers run in parallel because they operate in distinct data domains, a design choice explained in Section 3.4.

### 3.2 Hardware Components

This system is based on the ESP32 microcontroller which was chosen for its high performance (4MB of flash and dual cores) and the large overhead for running compressed TinyML models, as well as to accommodate a WiFi stack for cloud based telemetry. Two sensors model the typical monitoring signals on industrial semiconductor test equipment. An MPU6050 six-axis IMU is included to monitor vibration and mechanical health over I2C, modeling the forces exerted on the unit in a high speed handler. A DHT22 sensor is included to monitor environmental and thermal stress, such as that experienced within a High-Temperature Operating Life chamber, by outputting digital temperature and humidity values over a single GPIO pin. Local feedback to an operator regarding device state is provided by a Green and a Red LED. Green lights up if the system is operating normally, Red lights up when a failure or threshold condition is detected. The MPU6050 connects via I2C (GPIO 21/22), while the DHT22 (GPIO 4) and the red and green LEDs (GPIO 18 and 19) each use individual digital pins.

### 3.3 Software Architecture

The software stack is built on the Arduino ecosystem with libraries specifically added to handle hardware abstraction and connectivity to the cloud. Data collection from the sensors is performed by the Adafruit MPU6050 library and DHT sensor library, giving us a structured representation of the I2C and digital bit stream of readings. The XGBoost classifier was successfully ported from Python to a standalone C score() function using m2cgen, after the alternative quantised framework (emlearn) caused severe precision loss in initial deployment tests. This double precision output preserves the model’s logic as is, essential as the SECOM features are Z-score standardised. System logic is handled by a BlynkTimer responsible for two asynchronous tasks: polling sensors at two-second intervals and running inference at five-second intervals. The ESP32 maintains a continuous WiFi connection to the cloud through the Wokwi-GUEST where results are pushed to ten virtual pins (V0–V9) in the Blynk web dashboard.

### 3.4 Two-Tier Architecture: Justification

The two-tier architecture is a deliberate design choice. It mirrors how modern semiconductor manufacturing combines multiple data sources at different layers. The real-time IoT stream on the physical testing apparatus is segmented from the TinyML inference run on high-complexity process telemetry data. The motion and temperature of the system's hardware is streamed live through the IoT layer, but processed through a model operating on standard SECOM process samples. The partitioning is mandated by a core domain mismatch, as the input data consists of exterior physical health on the testing apparatus itself (vibration and ambient temperature), whereas the SECOM data describes interior process behavior (gas flows, pressures, and voltages). In a manufacturing setting, both data types exist side-by-side, but represent disparate fault vectors: vibration analysis measures the health of the mechanics in high-speed handlers, and process telemetry detects silicon manufacturing phase drift. The two tiers are thus co-located onto a single ESP32 to form a 'capability-complete' edge device. This is evidence that the microcontroller can simultaneously manage high-bandwidth IoT telemetry and high-dimensional AI inference. Simply piping raw vibration signals from the MPU6050 into a trained SECOM chemical process model would result in a technically unsound application of the model; here, the focus is on verifying the ability of the device to handle the resource load of parallel, independent computation with each domain. This creates an accurate testing environment for hardware capabilities with regards to computational load and avoids corrupting the carefully prepared SECOM dataset. The two tiers remain independent in this implementation. Their inter-domain integration via intelligent sensor fusion becomes the primary direction for future research described in Section 8.

### 3.5 Section Summary

This two-tier approach presents a balance between an illustrative IoT demonstration and a practical implementation study of a high-dimensional ML model. It validates that the ESP32 can fulfill its dual role of streaming raw, real-time environmental telemetry and performing sophisticated process-level inference. The model selection, training procedure, and necessary adjustments to account for the SECOM dataset are described in Section 4, and the full system implementation and verification are described in Section 5. This system has been successfully implemented and tested: real-time sensor data is reliably streaming to the cloud dashboard and ML inference produces predictions matching the original Python implementation.
